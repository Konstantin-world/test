# Git workflow

## Ветвление

```
main ──────●───────●───────●──→  (всегда стабильна)
            \     / \     /
             ●───●   ●───●
          feat/login fix/npe
```

`main` — единственная долгоживущая ветка. Прямые пуши в неё запрещены,
изменения попадают только через Pull Request.

## Именование веток

| Префикс | Когда |
|---|---|
| `feat/` | новая функциональность |
| `fix/` | исправление бага |
| `chore/` | инфраструктура, конфиги, уборка |
| `docs/` | только документация |
| `refactor/` | правки без изменения поведения |

## Conventional Commits

```
<type>(<scope>): <описание в imperative, до 72 символов>

Что и почему — а не как. Тело коммита объясняет мотивацию.

Refs: #123
```

Типы: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.

## Правила хорошего коммита

1. **Атомарность** — один коммит = одна логическая правка.
2. **Сборка не сломана** — каждый коммит компилируется и проходит тесты.
3. **Описание, а не констатация** — `fix: guard against nil user`, не `fix bug`.
4. **Никаких секретов** — `.env`, ключи и токены блокирует `.gitignore`.
