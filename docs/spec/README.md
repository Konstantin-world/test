## Каталог упражнений — как он устроен

`content/exercises.json` является **порождаемым артефактом**. Источник правды —
`tools/gen-catalog.py`, где все 60 упражнений лежат в одной компактной таблице:

```bash
python3 tools/gen-catalog.py        # пересобрать exercises.json
node tools/validate-content.mjs     # проверить
```

Генератор попутно сверяет целостность: существование доменов, архетипов и тегов,
уникальность id, допустимость оценок доказательности, отсутствие мёртвых
параметров сложности (`at0 == at1`), запрет активного упражнения на
retired-архетипе. Это ловит опечатки, которые JSON-схемой не поймать.

## Платформенность: почему архетипы, а не экраны

Обещание «постоянное дополнение упражнениями» выполнимо только потому, что
60 упражнений сведены к **13 архетипам** взаимодействия. Распределение:
`single_choice` = 19, `stateful_board` = 11, `numeric_input` / `sequence_recall`
/ `timed_field` = по 5, остальные меньше.

| Действие | Что требуется |
|---|---|
| Новое упражнение на существующем архетипе | Обновление контента. **Релиз не нужен** |
| Новое упражнение на новом архетипе | **Релиз приложения** |

Отсюда единственное настоящее платформенное требование: набор архетипов
проектируется с запасом. Запланированный `rhythm_timing` (ритм-игра под музыку)
описан в `archetypes.json.future` заранее — чтобы клиент заложил аудио-тайминг
от `audioContext.currentTime`, а не от `setTimeout` (джиттер 10–30 мс при окне
попадания ~50–100 мс делает игру невозможной).

## Проверка

Контент валидируется исполняемым скриптом, а не «на глаз»:

```bash
node tools/validate-content.mjs
```

Проверки: схема полей, целостность ссылок на домены, монотонность кривых
сложности, покрытие всех 8 доменов в MVP, соответствие квоте «10–12 упражнений»
из дорожной карты. Подключено к CI.

## Почему это отдельный слой

Продуктовая спека задаёт Kotlin + Jetpack Compose. Это правильное решение для
Android-first продукта, но оно не отменяет того факта, что **ядро продукта —
не UI, а алгоритмы**: адаптивная сложность, композитор сессии, «Индекс ясности»,
интервальное повторение. Это чистая логика без платформы.

Вынесение её в machine-readable спецификацию даёт три вещи:

1. **Один источник правды** — каталог упражнений читается и Kotlin-кодом,
   и тестами, и CI, и (позже) бэкендом контент-сервиса.
2. **Портируемость** — смена платформы не переписывает продуктовую логику.
3. **Проверяемость** — схемы и инварианты валидируются автоматически,
   до того как код увидит рантайм.
