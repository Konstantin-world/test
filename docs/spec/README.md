## Проверка

Контент валидируется исполняемым скриптом, а не «на глаз»:

```bash
node tools/validate-content.mjs
```

Проверки: схема полей, целостность ссылок на домены, монотонность кривых
сложности, покрытие всех 8 доменов в MVP, соответствие квоте «10–12 упражнений»
из дорожной карты. Подключено к CI.

## Почему это отдельный слой

Продуктовая спека задаёт Kotlin + Jetpack Compose. Это правильное решение для
Android-first продукта, но оно не отменяет того факта, что **ядро продукта —
не UI, а алгоритмы**: адаптивная сложность, композитор сессии, «Индекс ясности»,
интервальное повторение. Это чистая логика без платформы.

Вынесение её в machine-readable спецификацию даёт три вещи:

1. **Один источник правды** — каталог упражнений читается и Kotlin-кодом,
   и тестами, и CI, и (позже) бэкендом контент-сервиса.
2. **Портируемость** — смена платформы не переписывает продуктовую логику.
3. **Проверяемость** — схемы и инварианты валидируются автоматически,
   до того как код увидит рантайм.
