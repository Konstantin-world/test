# Адаптивный движок сложности

Статус: **специфицировано, готово к реализации**. Языконезависимо.

Бриф (раздел 3) задаёт требование: *«параметры каждой игры меняются в реальном
времени на основе последних 3–5 результатов, целевой уровень успеха ~75–80%»*.
Это требование без конкретной формулы нереализуемо. Ниже — формула.

---

## 1. Скалярный индекс сложности

Каждое упражнение управляется **одним** числом `d ∈ [0, 1]`, а не набором
независимых параметров. Все параметры упражнения — функции от `d`:

```
int:    value(d) = round(at0 + (at1 - at0) * d)
float:  value(d) = at0 + (at1 - at0) * d
enum:   value(d) = values[round(d * (len(values) - 1))]
```

Контракт: `at0` — значение на самой лёгкой сложности, `at1` — на самой тяжёлой.
Направление «что сложнее» закодировано в самих значениях, отдельное поле не нужно.

**Зачем один скаляр.** Иначе для каждого из 16 упражнений нужна собственная
логика адаптации — 16 мест, где можно ошибиться, и 16 мест, которые надо
тестировать. Со скаляром адаптивный контроллер один, общий, и тестируется один раз.

---

## 2. Контроллер: трансформированная лестница Левитта

Правило:

> Сложность **повышается** после **3 подряд** правильных ответов.
> Сложность **понижается** после **1** неправильного ответа.

В терминологии [Levitt, 1971](http://bdml.stanford.edu/twiki/pub/Haptics/DetectionThreshold/psychoacoustics.pdf)
(7377 цитирований) это **1-up/3-down**, где «up» — шаг в сторону облегчения стимула.

**Точка схождения — 79.4% правильных ответов.** Это не подгонка, а известное
аналитическое свойство правила ([сводка точек схождения](https://metricgate.com/docs/transformed-up-down-staircase-levitt/)):

| Правило | Точка схождения |
|---|---|
| 1-up/2-down | 70.7% |
| **1-up/3-down** | **79.4%** ← цель брифа 75–80% |
| 1-up/4-down | 84.1% |

Выбор 1-up/3-down — единственное правило из стандартного семейства, попадающее
в заявленный диапазон. Никакой эвристики «если accuracy < 0.75, добавь уровень».

### Псевдокод

```
state:
  d                 # текущая сложность, [0, 1]
  step              # размер шага
  correctRun        # счётчик подряд правильных
  reversals         # список точек разворота
  lastDirection     # +1 | -1

init(d0):
  d = d0
  step = 0.08       # крупный шаг на старте, для быстрой сходимости
  correctRun = 0
  reversals = []

onResponse(isCorrect):
  if isCorrect:
    correctRun += 1
    if correctRun >= 3:
      stepUp()
      correctRun = 0
  else:
    correctRun = 0
    stepDown()

stepUp():
  move(+1)

stepDown():
  move(-1)

move(direction):
  if lastDirection != 0 and direction != lastDirection:
    reversals.append(d)          # разворот — порог найден
    if len(reversals) >= 2:
      step = max(step / 2, 0.02) # Левитт: halving после первых разворотов
  d = clamp(d + direction * step, 0, 1)
  lastDirection = direction
```

### Оценка порога

```
threshold(exercise) = mean(reversals[2:6])   # первые 2 разворота отбрасываются
```

Отбрасывание первых разворотов обязательно: до схождения лестница движется
с систематическим смещением в сторону стартовой точки.

---

## 3. Межсессионная память

Внутри одной сессии лестница не успевает сойтись (20–30 проб мало). Поэтому
порог оценивается **по нескольким сессиям** — это и есть «последние 3–5
результатов» из брифа.

```
persisted:
  dBaseline[exerciseId]   # EWMA сложности, с которой стартуем
  thresholdEwma[exerciseId]

startSession(exerciseId):
  d0 = dBaseline[exerciseId] ?? coldStart(exerciseId)

endSession(exerciseId, sessionThreshold):
  if sessionThreshold is not None:
    thresholdEwma = α * sessionThreshold + (1 - α) * thresholdEwma
    dBaseline     = clamp(thresholdEwma, 0, 1)
```

`α = 0.3` — компромисс между отзывчивостью и устойчивостью к одному плохому дню
(недосып, болезнь, отвлечение). При `α = 1` пользователь после неудачной сессии
получит заметно более лёгкие задания и заскучает; при `α = 0.1` адаптация
займёт месяцы.

### Холодный старт

До онбординга — `d0 = 0.30`. После онбординг-теста — линейное отображение
результата доменного теста в `d0 ∈ [0.2, 0.6]`. Выше 0.6 на старте не поднимаем:
первое впечатление важнее точности калибровки, а лестница дойдёт за 2–3 сессии.

---

## 4. Защита от фрустрации

Чистая лестница Левитта технически оптимальна, но продуктово опасна: серия
ошибок роняет сложность резко, и пользователь видит, что «деградирует».

| Правило | Значение | Обоснование |
|---|---|---|
| Минимальное время на уровне | 3 пробы | Не дёргать сложность на шумовой реакции |
| Максимум понижений подряд | 2, затем пауза на 5 проб | Прервать спираль «ошибка → легче → ощущение провала» |
| Визуальная индикация | сложность **не показывать числом** | Показывать прогресс, а не «вы упали на уровень 3» |
| Нижняя граница `d` | 0.05, не 0.0 | `d = 0` может дать вырожденно лёгкую задачу |
| Сообщение после 3 понижений | ободряющее, без сравнений | Геймификация «без давления» из брифа, раздел 6 |

---

## 5. Что НЕ адаптируется

Намеренно фиксировано, чтобы метрики оставались сравнимыми во времени:

- **Число проб на блок** (`trial.perBlock`) — иначе accuracy на 5 пробах и на 50 несопоставимы.
- **Порядок доменов в сессии** — задача композитора сессии, не контроллера.
- **Длительность сессии** — задаётся пользователем.

Если адаптировать и их тоже, «Индекс ясности» перестанет быть измерением и
станет художественным числом.

---

## 6. Агрегация до домена

```
domainScore(domain) = Σ (thresholdEwma[ex] * accuracy[ex] * weight[ex]) / Σ weight[ex]
                      по упражнениям домена, weight = 1 / recencyAge
```

`recencyAge` — давность последней сессии с упражнением, в днях. Свежие
результаты весят больше; упражнение, которое не открывали месяц, не должно
определять профиль.

---

## 7. Тестируемость

Контроллер детерминирован и не зависит от платформы. Обязательные тесты:

| Тест | Ожидание |
|---|---|
| Синтетический пользователь с `p = 0.80` | лестница сходится к `d`, где фактическая точность 79.4% ± 3% на 500 проб |
| Синтетический с `p = 1.0` | `d → 1.0` |
| Синтетический с `p = 0.0` | `d → 0.05` (нижняя граница) |
| Чередование верно/неверно | `d` осциллирует вокруг порога, развороты фиксируются |
| `step` уменьшается | после ≥2 разворотов `step` вдвое меньше начального, не ниже 0.02 |
| Защита от фрустрации | после 2 понижений подряд — пауза 5 проб |

Первый тест — ключевой: он проверяет не «код работает», а что **реализованная
точка схождения совпадает с теоретической 79.4%**. Это единственная настоящая
проверка корректности лестницы.
